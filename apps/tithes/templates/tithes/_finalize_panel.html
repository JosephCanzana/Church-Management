{% comment %} tithes/_finalize_panel.html THE finalize card of the review page: one place for Finalize, the finalize request (formerly "bypass request"), the admin's decision and "No tithes & offering". It replaces _finalize_form.html and _bypass_panel.html. Include only for a draft the person can finalize (`is_draft and can_finalize`). Context (tithes.views._report_context): report, sheet, totals, empty, is_admin, finalize_ready, has_approved, open_request, last_request, can_see_request, locked_for_you, can_request, can_withdraw, can_decide, finalize_token, request_token, decision_token. How it reads, by person: admin / super-admin Approve and finalize / Reject first when a coordinator's request is pending (approving finalizes the report at once, balanced or not). While a request is pending there is NO direct Finalize button. With no request: Finalize (with a reason when the numbers do not match), or "No tithes & offering" when empty. coordinator no request yet: the request button opens the modal (the modal itself is in report_review.html; message required only for a mismatch); pending: "waiting" and Withdraw. An admin's approval finalizes the report at once. (An already-approved request from before that change can still be finalized once.) The message and the decision note are shown only when can_see_request. Nothing here writes an amount anywhere. {% endcomment %}{% load people_tags %}
