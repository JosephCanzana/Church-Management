{% comment %} _push_card.html: the "Notifications on this device" card for the Settings page (Brick 12). Rendered by the {% push_device_card %} tag (notifications/templatetags/push_tags.py); do not include it directly. Variables: enabled, devices (the person's own PushSubscription rows), public_key, max_devices, csrf_token, next_url, can_test (True only for a superadmin; the tag must pass request.user.is_superuser). Behaviour lives in static/js/push.js (Alpine component pushDevice). Nothing is drawn when push is not set up. The status is always written as text, never by color alone; the switch also exposes aria-checked. Subscription endpoints and keys are never in this page. The devices list starts collapsed (nested Alpine scope, inherits thisHash). The test button is hidden for everyone except a superadmin. This is only a UX guard: the push:test view must check it too. {% endcomment %} {% if enabled %}
